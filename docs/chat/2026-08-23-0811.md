- masks (brush, gradients, luminance range, hue/color range, skin, sky/blue, subject/background later);
- ordered non-destructive edit stack with enable/disable, reorder, duplicate, reset, delete, opacity, copy/paste and presets;
- hold-original, bypass, split, swipe, flicker and synchronized two-image comparison;
- histograms, waveform, RGB parade, vectorscope, clipping overlays, false color and HDR nit overlays;
- pixel inspector exposing source/linear/perceptual values and HDR/gain-map state;
- advanced color management, soft proofing and gamut handling;
- RAW/DNG support later;
- high-end detail processing and denoise/sharpening improvements;
- chromatic-adaptation-based white balance and advanced WB tools;
- professional export profiles and batch export;
- batch editing;
- calibration/test imagery and device diagnostics;
- viewer rendering telemetry;
- crash-safe edit recovery;
- permanent test corpus;
- automated image-quality regression tests;
- touch-first editor UX with precision controls.

A new hard design rule was established:

> Every pixel-changing feature must either increase fidelity/correctness or be explicitly identified as a creative transformation/enhancement.

Reference mode must remain free of invisible beautification.

### Implementation order chosen

The first production implementation slice is the versioned non-destructive edit recipe model because all of the following depend on it:

- sliders/adjustments;
- undo/redo;
- masks;
- presets;
- persistent edits;
- crash recovery;
- copy/paste edits;
- sidecars;
- export rendering;
- forward compatibility.

The recipe design must be ordered, versioned, JSON serializable, source-identity-aware, and able to preserve unknown future operation types rather than making old builds destroy newer recipes.
